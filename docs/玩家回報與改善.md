# 玩家回報與專案改善

## 回報錯誤
在 GitHub Issues 頁面選擇「遊戲錯誤回報」，描述問題、預期結果與實際結果。請勿公開私人對話、真實個資或密碼。

## 回報主持品質
若主持者誤解玩家意圖、判定不合理、NPC 不合理知情、時間／物品狀態矛盾或存檔無法恢復，請選擇「主持者反思／模擬品質回報」。請提供可重現情境、預期與實際結果；只需提交去識別化資訊。

## 提出建議
選擇「遊戲建議」，說明新玩法的運作方式、預期效果，以及適用範圍：
- 全域共用：經審查後才可能加入所有玩家共用資料。
- 玩家可選：成為可選規則或模組。
- 單次模擬：只寫入該玩家自己的存檔，不污染全域世界觀。

## 修正閉環
每個問題依序經過分類、重現、根因分析、修正提案、紅隊反例、回歸測試及核准。GitHub Actions 只做確定性 QA，不呼叫 AI API，也不會自動改寫正式規則。

## 審查原則
回報不會自動改寫正式規則。維護者會先確認可重現性、正典相容性、玩家自由度、因果成本、平衡與隱私，再決定是否合併。
