# 霍格華茲資料庫完整度稽核

最後稽核：2026-11-25
範圍：GitHub main 分支目前可見的全域資料庫，不包含未公開的私人筆記或尚未提交內容。

## 一、結論

目前資料庫已有清楚的分類架構，但**尚未達到完整百科，更不是可直接支援所有場景的互動世界資料庫**。不少分類只有 README、條目模板或初始索引；人物、地點、物件、植物、生物、咒語及魔藥的深度與覆蓋率差異很大。

資料庫應拆成兩種完整度：
1. **百科覆蓋率**：這個世界有哪些人物、地點、物種、咒語、制度、事件與物品。
2. **模擬可用度**：主持者是否知道它的年代、位置、條件、限制、關聯、互動方式與來源，能否在遊戲中正確使用。

只增加名稱清單，不代表資料庫已可用。

## 三、優先補完的資料類別

### P0：直接影響模擬能否成立
1. **人物資料庫**
   - 1991 年全校重要學生、教授、職員、幽靈、肖像與校園居民。
   - 每人：姓名、年齡／年級、學院、家庭、外觀、公開性格、目標、關係、出場年代、已知資訊與原著來源。
   - 角色必須分年代，不能把不同時期的人物狀態混用。

2. **城堡地點與空間關係**
   - 逐樓層、塔樓、地下區域、教室、交誼廳、宿舍、廁所、醫療翼、圖書館、廚房、庭院、球場、溫室、校長室等。
   - 每地點記錄入口、出口、相鄰區域、通行限制、常駐人物、開放時間、可互動物件、秘密與來源。
   - 密道、移動樓梯、隱藏房間必須分成已確認、推測與劇情揭露，不能把粉絲地圖當正典。

3. **學年與課程運作**
   - 七年級課程進度、每科教材、課堂活動、作業、考試、成績標準、教授教學風格。
   - 學期、假期、節慶、魁地奇賽程、考試週、校內活動及每週日常節奏。
   - 完整課表若原著未提供，明確標為模擬用排程，不冒充官方課表。

4. **互動物件**
   - 書籍、信件、門鎖、肖像、樓梯、壁爐、坩堝、天平、望遠鏡、掃帚、藥草、魔法器具。
   - 每件重要物品需有狀態、互動方式、前置條件、耗時、消耗、風險與狀態變化。

### P1：提升世界深度
5. 咒語百科：逐咒語效果、範圍、限制、反制、施法條件、年代與首次出現來源。
6. 魔藥百科：用途、材料、配方完整度、器具、時間、火候、失敗風險、副作用與解藥。
7. 植物與生物：棲地、外觀、習性、照護、危險、材料用途、法律限制與可互動行為。

10. 魔法社會：家族、媒體、職業、魔法部、銀行、醫療、法律、交通與跨國制度。

## 四、每筆百科條目的統一標準

- 唯一 ID、中文名、英文原名、別名。
- 類別與標籤。
- 內容摘要與詳細描述。
- 適用年代、地點、年級或使用條件。
- 功能、限制、風險、互動方式。
- 關聯人物、地點、物品、咒語、事件。
- 角色可能知道的資訊與保密資訊（主持層資料需隔離）。
- 正典層級：原著小說／官方補充／電影／遊戲／舞台劇／粉絲整理／本模擬原創。
- 來源 URL、書名與章節（可核實時）、核對狀態、最後更新日。
- 不確定欄位明確標「未詳／待核對」，不以推測填滿。

## 五、來源與研究規範

1. 原著小說是主要依據；官方 HarryPotter.com Fact Files 與文章可補充官方世界觀。
2. 電影、Hogwarts Legacy 等遊戲、舞台劇資料分層收錄，不能混為小說正典。
3. Harry Potter Lexicon 等粉絲研究可用來找線索、交叉索引與定位章節；其地圖或推論必須標記粉絲整理，不可升格成正典。
4. 粉絲資料、搜尋摘要或 AI 記憶不能單獨作為高爭議事實的證據。
5. 不複製整段受版權保護的百科或小說內容；以自己的話整理短摘要，附來源。
6. 若不同來源矛盾，並列差異、年代與媒介，不強行合併成單一答案。

## 七、建議執行順序

先補「能讓玩家做事」的資料，而不是追求百科數量：
1. 建立地點、物件、人物三種互相關聯的資料卡。
2. 建立日常生活、課程、時間、商店與互動流程。
3. 補齊玩家常會用到的咒語、魔藥、植物與生物。
4. 按 1991–1992 年逐年核對人物與事件。
5. 每次新增條目都附來源、正典層級與可用於模擬的互動欄位。
